Z-Agent-Termux 以 shadow_test 与 boot_guard 双闸门防宕机：shadow_test 在隔离沙箱中用假 LLM 驱动候选代码跑完整会话并断言运行时不变量，失败即拒绝落盘；boot_guard 独立于主程序，在启动前做 AST、符号和冒烟自检，通过则快照 last_good，失败则原子回滚并复检。前者守住进化入口，后者守住启动入口，二者串联确保改崩也能回到最近可用版本，系统始终可启动。

💡 为什么做这个项目？
在 Android 手机上跑 AI Agent，最怕的就是“代码改崩了，救不回来”。
本项目实现了看门狗（boot_guard）+ 影子沙箱（shadow_test），即便改到启动崩溃，也能自动回滚。这是一套带自愈能力的移动端 Agent 实验架构。

【Z-Agent v6.1 超级智能终端 · 部署与使用说明书】

欢迎体验！
这是一个运行在 Android Termux 上的超级自主智能体。它不仅是一个脚本，它拥有心智（记忆/身份）、基因（源码）和能力（插件）。
最核心的是，它自带看门狗（boot_guard）和影子沙箱（shadow_test），即使改崩了也能瞬间回滚，拥有极强的自愈能力。

## ⚡ 一键部署（最推荐）

无需逐个复制命令，直接在 Termux 中运行以下代码即可完成全自动安装：

`curl -sL https://raw.githubusercontent.com/zxxzxx1314/Z-agent-termux/main/deploy.sh | bash`

*(注：如果 raw.githubusercontent.com 打不开，请使用 GitHub 加速服务，或直接下载 ZIP 包手动解压)*

【第一步：环境准备】（仅需 3 分钟）

1. 安装 Termux（推荐从 F-Droid 下载）。
2. 打开 Termux，依次复制执行以下命令：
   pkg update && pkg upgrade -y
   pkg install python unzip -y
   pip install requests

【第二步：部署 Z-Agent】

1. 把你收到的 zagent_share_final.zip 放到手机存储的 Download 文件夹。
2. 在 Termux 里执行以下命令解压并进入目录：
   unzip ~/storage/downloads/zagent_share_final.zip -d ~/
   cd ~/zagent_share_dir
   chmod +x start_agent.sh switch_api.sh
3. 关键一步：配置自己的 API 密钥
   由于分享包里已经剔除了原作者的密钥，你需要准备自己的 DeepSeek API Key（去 platform.deepseek.com 获取并充值）。
   你可以用一键切换脚本快速配置：
   ./switch_api.sh
   （选择 1 官方接口，粘贴自己的 Key 即可，它会自动安全地帮你写好配置文件）
4. 初始化防身备份（强烈建议，只需 5 秒）
   在 ~/zagent_share_dir 目录下执行以下命令，建立一个绝对安全的初始备份：
   cp zagent.py zagent.py.bak_final
   cp -r zcore zcore.bak_final
   cp -r zguard zguard.bak_final

【第三步：启动与基本操作】
启动命令：
./start_agent.sh
（建议用 Termux:Widget 把 start_agent.sh 做个桌面小组件，点一下就能启动）

进去之后，你是宿主，它是你的秘书。常用指令如下：
/auto     切换全自动模式（强烈建议日常保持关闭状态，按 y 确认执行）
/help     查看所有可用命令
/contract 查看当前任务验收合同
/exit     退出程序

【核心玩法：三层进化法则】（极其重要！）
这是原作者耗时 8 小时与它磨合出的“宪法”，请一定要遵守这三条铁律，否则它很容易死机：

★ 第一层：能力进化（占 90% 的日常使用） —— 强烈推荐
怎么做：直接给它派发日常任务。
万能提示词模板：“请帮我写一个 Python 脚本，功能是 [你的需求，比如把 ~/Download 里的 jpg 压缩一半]，要求 [特殊要求，比如要有进度提示]。写完并执行成功后，告诉我。”
固化技能：它执行成功、退出码为 0 后，立刻输入 /save 压缩图片
成果：以后你只要输入 [plugin:压缩图片]，它就能瞬间帮你一键干活。

★ 第二层：心智进化（调教它的性格和习惯）
怎么做：直接跟它说你的要求，例如：“以后回答我请精简一点，不要长篇大论。”
成果：它会自动通过 [identity] 标签重写系统提示词，下次启动立刻生效，记忆永久保留。

★ 第三层：基因进化（修改源码） —— 【宿主绝对禁区】
· 绝对不要在手机上让它自己重构源码（如 /evolve）。
· 它现在的源码架构极其精密（拥有 zcore 和 zguard 物理隔离）。如果在手机上强行改源码，100% 会因内存溢出或正则解析失败导致彻底瘫痪。
· 如果必须修 Bug，请把 zagent.py 导出到电脑，用 VS Code 修改、测试通过后，再传回手机覆盖。手机是用来“用”它的，电脑才是用来“改”它的。

【血泪避坑指南】（必读）

1. 千万不要用 nano 改源码：手机屏幕太小，上下滑动极易误删代码。一旦误删，即便是影子沙箱也救不回缺失的函数。要改配置，用 sed 命令或配置脚本。
2. 严禁把 mind 文件夹发给别人：mind 里包含了机器人的“灵魂”（日记、技能库、历史合同）。如果你要把这套系统发给朋友，务必先清空 mind 文件夹，让它从初生状态开始，而不是窃取你的记忆。
3. 关于 API 报错：
   · 遇到 401：密钥错误，检查有没有复制错。
   · 遇到 402：账户余额不足。
   · 遇到 503 / 524：服务商宕机或并发过高（建议弃用便宜的日卡，直接充值 DeepSeek 官方，稳定丝滑）。
4. 关于“它不说话了”：它的输出是非流式（一次性吐出全部内容）。如果网络慢，屏幕会卡住，但只要光标在闪，就没死。超过 3 分钟没反应，直接按 CTRL + C 打断。

【结语】
不要把它当成一个“玩具”，请把它当成你手机里最靠谱的自动化助理。
去用它，去驯服它，去给它写无数个插件，让它在你的指挥下，每天替你省下 10 分钟的生命。

【常见问题（FAQ）与终极补救指南】
==================================================

Q1：我一不小心改错了源码，启动直接闪退/报错/黑屏怎么办？
A：不要慌！你拥有全自动的“看门狗”救生舱，按以下顺序尝试恢复：
方法一（自动回滚）：重启终端，看门狗（boot_guard）检测到启动失败，会自动读取上一个快照并回滚，你再次运行 ./start_agent.sh 即可恢复。
方法二（手动回滚）：如果看门狗也被改坏了，请回到 ~/zagent_share_dir 目录下，执行以下命令，用我们在第二步建立的“初始备份”进行恢复：
   cd ~/zagent_share_dir
   cp zagent.py.bak_final zagent.py
   cp -r zcore.bak_final/* zcore/
   cp -r zguard.bak_final/* zguard/
   ./start_agent.sh
方法三（终极重装）：如果以上都不行，直接删掉这个文件夹，把当初的 zagent_share_final.zip 重新解压一次，10秒钟满血复活。

Q2：我想换一个中转站（或换 Claude / GPT 等其他模型）怎么操作？
A：用一键切换脚本。
在 ~/zagent_share_dir 目录下执行：./switch_api.sh
选择 "2. 自定义"，然后依次输入对方提供的 API 地址（URL）、模型名称、API Key。它会自动修改代码里的 BASE_URL 和 MODEL 变量，无需你自己改源码。

Q3：为什么我接入了便宜的日卡，总是报 503 或 524 错误？
A：因为 2 块钱左右的“日卡/共享卡”通常有极高的并发限制，而且服务器极不稳定，动不动就宕机。Z-Agent 运行时会频繁调用 API（写代码、自检、反思），日卡根本扛不住。强烈建议使用 DeepSeek 官方 API（充 10 块钱能用很久）。

Q4：为什么它每次启动，加载都很慢，且消耗的 API 额度很高？
A：因为它的 mind 文件夹里存放了完整的日记（journal.md）和自主问题队列（problems.md）。每次启动它都会把这些历史记录读进“大脑”。如果你觉得消耗太快，可以编辑 ~/zagent_share_dir/mind/journal.md，把历史内容清空，它就能轻装上阵。

Q5：全自动模式（/auto）好用吗？可以一直开着吗？
A：极其不建议！全自动模式下，它一旦陷入逻辑死循环，会在几秒钟内疯狂请求 API 烧钱，甚至把文件改乱。日常使用时建议保持 /auto 关闭，看到它请求执行脚本时，手动输入 y 允许即可。只有在确认任务绝对安全（比如纯计算脚本）时，才临时开启。

Q6：如何把当前目录打包，分享给另一个朋友？
A：执行以下命令即可打包你的代码（注意：清理掉 mind 文件夹，或者手动打码敏感信息）：
   cd ~
   zip -r zagent_share.zip zagent_share_dir/*
   cp zagent_share.zip ~/storage/downloads/

【补充篇一：不同水平使用者的生存指南】
==================================================

无论你是第一次接触命令行的小白，还是精通架构的高级开发者，在使用本系统前，请务必对照以下特征，选择自己的安全策略。

【类型一：纯新手（第一次用 Termux，不懂 Python）】
* 你的风险：拼写错误（少打空格、误删符号），复制命令时把提示符也复制进去，遇到报错就 panic。
* 生存法则：
  1. 绝对复制粘贴，不要手打命令。
  2. 只做第一步：跑 ./start_agent.sh。输入任务，按 y 执行，保存为插件。
  3. 千万不要去碰 ~/zagent.py 和 zcore/ 目录，把它们当成黑盒。
  4. 如果系统崩溃，不要试图自己修。直接删掉整个文件夹，重新解压一遍分享包，10秒钟满血复活。

【类型二：有一定技术基础的程序员（会写 Python，懂 Linux）】
* 你的风险：觉得“自己上我也行”，尝试用 nano 修改源码，或者手动调整系统变量，导致逻辑崩坏。
* 生存法则：
  1. 请务必把“三层进化法则”刻在脑子里：心智指方向，基因守底线，能力打天下。
  2. 不要碰 zcore 和 zguard。你的所有开发需求，都必须转化为“让 Agent 写脚本 -> /save 存为插件”这条路径。在插件层折腾，坏了重写就是了。
  3. 如果确实需要改底层源码，请把源码拷到电脑上，在电脑上完成修改和测试，再传回手机。手机只是运行终端，不是开发环境。

【类型三：自负的高级玩家（觉得 AI 能自我进化，疯狂跑 /evolve）】
* 你的风险：觉得“有看门狗和影子沙箱，随便改”，频繁让 AI 重构底层，导致系统逻辑越来越臃肿，最终出现无法预测的死锁或内存溢出，且你自己都不知道是哪一行改坏的。
* 生存法则：
  1. 影子沙箱只能拦住“静态全绿，运行必崩”的逻辑错误，它无法模拟真实的安卓环境和网络交互。
  2. 任何 AI 生成的代码，在通过沙箱后，也必须先备份，再进行替换。
  3. 永远保持一个“干净的、可运行的 v6.1 完全体备份”。任何重构尝试，如果最终失败了，果断放弃，回退到备份，不要死磕。

【补充篇二：系统架构认知与长期维护指南】
==================================================

当你熟悉了如何指挥它工作后，你需要建立对它的“养护认知”。这台手机里的 Agent 不是一次性脚本，而是一个有生命周期的软件资产。

【核心认知：它的“生理结构”】
为了让你在面对崩溃时心里有底，你必须了解它的三个核心部位：
1. zagent.py：它的“大脑皮层”（主程序逻辑）。
2. zcore/ 和 zguard/：它的“基因与免疫系统”（提取出的工具库、看门狗、影子沙箱）。
3. ~/mind/：它的“灵魂与记忆”（身份、日记、技能库、验收合同记录）。这也是你最需要保护和备份的文件夹。

【核心能力一：版本回退与历史查看（时光机）】
如果某次让它执行任务出了岔子，或者它自我进化后变得不好用了，你可以使用它的“时光机”：
· /versions   查看基因谱系（所有历史备份的列表）。
· /rollback N 回滚到第 N 代基因（只需输入序号，它就会自动切回那个版本并重启生效）。

【核心能力二：灵魂的备份与迁移】
如果要换手机，或者你想把当前“已经培养出感情”的 Agent 原封不动搬到别的设备上，你不需要搬整个文件夹。
你只需要：
1. 备份它的“灵魂”：把整个 ~/mind 文件夹复制出来（这里面有它的一切记忆和习惯）。
2. 在新手机上重新部署一次干净包。
3. 把新手机上的空 mind 文件夹删掉，用你备份的 mind 覆盖进去。
4. 执行 ./switch_api.sh 填入新手机的 API Key。
启动后，它就会带着之前的记忆和技能，在新设备上无缝复活。

【核心能力三：防止“老年痴呆”与“破产”（降本增效）】
长期养一个 Agent，最大的开支是 API 费用。如果你发现它越来越慢、越来越贵，请执行以下操作：
1. 定期清理日记：打开 ~/mind/journal.md，把超过一周的、没有参考价值的“日常流水账”删掉。这能显著降低每次启动的 Token 消耗。
2. 清理冗余技能：如果 ~/skills/ 里有大量重复或已经失效的反思笔记，可以手动删除。让它的知识库保持精炼。
3. 善用 deepseek-flash：日常的整理文件和简单运算，使用官方最便宜的 flash 模型。只有在需要它重构复杂逻辑时，才临时切到高配模型。
4. 绝不开着 /auto 挂机：它不睡觉，只要开着全自动，它就会一直思考并消耗你的余额。用完就 /exit 退出。

【核心能力四：插件库是唯一的“真本事”】
请记住，不要以“代码重构了多少次”来衡量它的进化程度。唯一能证明它变强的标准是：
~/.plugins/ 文件夹里，到底存了多少个你真正在日常使用的插件。
· 每写一个有用的脚本，就 /save 存下来。
· 当你的插件库积累到 20 个以上时，它才是真正属于你的“效率武器库”。

【最后的忠告：造物主的边界】
你或许觉得它无所不能，甚至想让它自己去修改自己的源码。请一定要克制这种冲动。
· 它现在的架构（物理隔离 + 影子沙箱）已经是手机端的工程极限。
· 任何试图在手机上二次重构 zcore 的行为，99% 会以系统崩溃告终。
· 正确的做法是：手机用来运行（使用插件、写脚本），电脑用来开发（改源码、传回手机）。
造物主最大的智慧，不是无限施压，而是划定边界，各司其职。
